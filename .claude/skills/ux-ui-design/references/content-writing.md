# Content Writing — site descriptions & page copy

Trigger: "เขียนคำอธิบายเว็บ", "เขียน about us", "คำอธิบายสินค้า", "meta description",
"เขียนเนื้อหาหน้าเว็บ". For button/label/error text see [copy](copy.md).

## 1. Ask (max 3)
Who reads it · what they should do after · brand tone (friendly / formal / premium / fun).
Use only real facts the user gives; mark missing ones `[ใส่ข้อมูล]`. Never invent reviews,
numbers, awards or claims.

## 2. Formulas

| Piece | Length | Formula |
| --- | --- | --- |
| Headline | ≤ 8 words | Value for the reader, not your name |
| Subline | ≤ 20 words | Who it's for + how + proof |
| Site description (1 line) | ≤ 25 words | We help [who] [do what] by [how] |
| Meta description | 120–155 chars | Value + key word + call to act |
| `<title>` | ≤ 60 chars | Page topic – Brand |
| About us | 3 short paragraphs | Why we exist → what we do → why trust us |
| Product / service | 3–5 bullets | Benefit first, then spec; price + CTA |
| Feature block | title ≤ 4 words + 1 line | What it does for the user |
| FAQ | Q in user's words, A ≤ 2 lines | Answer the worry directly |
| CTA section | 1 line + button | Restate value + verb button |
| Social / OG | ≤ 90 chars | Hook + benefit |

## 3. Style
- Short sentences (≤ 12 words). One idea per paragraph.
- "You" more than "we". Benefits before features.
- Plain words users say; no buzzwords ("ครบวงจร", "นวัตกรรม", "ที่สุด") without proof.
- Scannable: headings, bullets, bold key words.
- Thai: polite but not stiff; avoid "กรุณา" overuse; consistent "ค่ะ/ครับ" or none. See [thai-ui](thai-ui.md).
- No emoji in UI copy.

## 4. Output
Give 2 versions (e.g. friendly vs formal) for headline + description; the rest in one
voice. Mark every `[ใส่ข้อมูล]` and any assumption.

## Example
```
Headline:     จองโต๊ะได้ใน 30 วินาที
Subline:      ร้านอาหารไทยย่านอารีย์ เปิดทุกวัน 11:00–22:00
Description:  เราช่วยคนทำงานแถวอารีย์หาข้าวมื้ออร่อยโดยไม่ต้องรอคิว
Meta:         ร้านอาหารไทยอารีย์ จองโต๊ะออนไลน์ง่าย ไม่ต้องรอคิว ดูเมนูและเวลาเปิดได้ที่นี่
```
